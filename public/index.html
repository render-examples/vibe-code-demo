Starting

  1. The architect agent reads the prompt and plans the app: its pages, its content, and the Render resources that it needs. Runs in The architect task on Render Workflows
  2. Starts a real Postgres in the sandbox, so that the builder can test its schema and seed data. An app without a database skips this stage. Runs in The Render Sandbox of this run
  3. Finds openly licensed photographs on Wikimedia Commons and downloads them into the app. No model chooses a URL or a file name. Runs in The prompt-to-app task on Render Workflows
  4. The builder agent writes the app: it selects the stack, writes the files, and runs commands. It also fixes each failure that verification finds. Runs in The builder task on Render Workflows. Its tools run in the Render Sandbox, which holds no credentials.
  5. Builds the app from only the files that a commit holds, as Render will. Then it boots the app and checks its endpoints. Runs in The verify-app task on Render Workflows. The builds run in the Render Sandbox.
  6. Copies the app into a clean clone of the apps repository, writes its Blueprint, and pushes one commit to GitHub. Runs in The publish-app task on Render Workflows, in a second Render Sandbox that no agent uses
  7. The push starts a Blueprint sync. Render creates the project and the services of the app from render.yaml. Runs in Render. The prompt-to-app task waits on the Render API.
  8. Render builds and deploys each service. If a deploy fails, the deploy manager agent finds the cause in its logs, and the builder fixes it. Runs in Render. The prompt-to-app task waits on the Render API. A repair runs in the deploy-manager and builder tasks.
  9. Render says that the app is live. Now the workflow requests its public URLs and checks the storefront, the data, and CORS. Runs in The prompt-to-app task on Render Workflows
  10. The app passed every check and is live on Render. Runs in The app's own project on Render
